# Job Apply (Greenhouse, Lever) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From Talk, open one Himalayas job's application form (Greenhouse or Lever), fill it from the admin's
answer bank, ask the admin for the rest, attach the CV, and stop before Submit.

**Architecture:** A pure module `govaios/formfill.py` reads a form from the neutral accessibility tree and matches
fields to the bank by a fixed rule (no model). The engine gains `fill_form` and `attach_file` steps that gate
each action as before. The run (network-less) and the panel talk through 0600 files in the data home. The flow
`job_apply` and three page schemas wire it together. Runs take one input, the job link, passed from the Talk card
through the launch helper as an env var.

**Tech Stack:** Python 3, PyYAML, pyobjc (macOS AX/CGEvent), pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-07-greenhouse-apply-design.md`

## Global Constraints

- No AI model anywhere in the run-time path. Label-to-answer matching is the fixed rule in Task 2.
- Answer values (bank or admin) never appear in the audit log, stdout/stderr, reports, `result.json` or
  exception messages. Labels (form question text) may.
- The flow has `max_element_risk: modify`. `Submit application`, `SUBMIT APPLICATION`, `Autofill my application`
  and `Apply with LinkedIn` are rated `submit` and can never be clicked.
- Flow destinations are exactly `https://www.google.com`, `https://himalayas.app`,
  `https://job-boards.greenhouse.io` and `https://jobs.lever.co`.
- Never auto-filled, always to the admin: secure fields, and labels matching the sensitive, demographic or
  consent patterns (Task 2). Pronoun checkboxes and any checkbox group count as demographic.
- A field that already has a value is never changed.
- Every data-home file this plan adds (`apply/answers.yaml`, `apply/ask.json`, `apply/reply.json`,
  `apply/result.json`) is mode 0600, created with `O_NOFOLLOW`. The directory is 0700.
- `ASK_TIMEOUT_S = 900`; at most `FORM_PASSES = 3` read passes.
- Tests: `.venv/bin/python -m pytest -q`; the suite must stay green (722 passed at plan time).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feat/job-apply`.

## Rulings (where this plan narrows the spec)

- **Picking the job:** `/job-apply` takes a pasted Himalayas job link instead of listing JobLens applications.
  The panel's sandbox (`UI_PROFILE`) has no outbound network, so a list needs a sandbox change: a separate
  decision for the admin. Cost if wrong: one follow-up task.
- **The CV is attached as a file only.** Greenhouse's "Enter manually" paste mode is deferred, since Lever has
  no paste option and needs the file path anyway.
- **The panel writes "save to my bank" entries when the admin answers,** not when the run ends: one writer, and
  the run read the bank at its start.
- **No CAPTCHA detection.** The admin presses Submit, where challenges appear. A challenge earlier makes a fill
  fail its read-back, and the field goes to "fill yourself".
- **Disabled fields aren't detected** (the adapter doesn't read `AXEnabled`). A fill on one fails read-back and
  the field goes to "fill yourself".
- **Character limits aren't read** (AX has no maxlength). A too-long answer fails read-back and the field goes
  to "fill yourself".
- **If Himalayas' Apply opens a new window rather than a tab,** the pinned-window check refuses input and the
  run stops. That's acceptable for v1; the live test will show which happens.
- **`fill_form` is one flow step** that gates `fill_field` and `ask_admin` per action; there are no separate
  `read_form`/`ask_admin` steps.

## Review Focus

1. The page re-renders between reading and filling (React), so node handles go stale. Each fill re-finds its
   field by key in a fresh snapshot. Test in Task 5.
2. A field already has a value (Chrome autofill, or the admin typed). It's never touched and is listed as
   "check yourself". Test in Task 5.
3. Two fields share a label with no ids (e.g. "Phone" twice). Both go to the admin; neither is filled from the
   bank. Test in Task 3.
4. The admin never answers or closes the panel. After 900 s the run stops, and `ask.json` and `reply.json` are
   removed. Test in Task 5.
5. The bank YAML is malformed, or edited while a run waits. Loading fails closed with field names only, and the
   run uses the bank as read at its start. Tests in Task 2 and Task 8.

### Task 2: Answer bank and matching rule (`formfill`, part 1)

**Files:**
- Create: `govaios/formfill.py`
- Test: `tests/test_formfill.py`

**Interfaces:**
- Produces:
  - `normalize(label: str) -> str`: lower case; drop trailing `*`, `✱` and whitespace; replace every character
    that isn't a letter, digit or space with a space; collapse spaces; strip.
  - `class BankError(ValueError)`: the message names fields or line numbers only, never values.
  - `@dataclass(frozen=True) Entry(key: str, labels: tuple[str, ...], answer: str)`
  - `@dataclass(frozen=True) Bank(entries: tuple[Entry, ...] = (), cv_file: str | None = None)`
  - `load_bank(path: Path, user_home: Path) -> Bank`: a missing file gives `Bank()`. YAML shape:
    `{cv_file: str?, answers: [{key: str, labels: [str], answer: str}]}`. Keys match `[a-z0-9_]{1,40}`;
    1–20 labels of at most 300 chars; answers of at most 2000 chars; at most 300 entries; no duplicate keys.
  - `cv_path(bank: Bank, user_home: Path) -> Path | None`: `~` expands to `user_home`. Returns the realpath only
    if it is a regular file, not a symlink (`os.lstat`), inside `user_home`, with suffix `.pdf`, `.doc` or
    `.docx`; else `None`.
  - `RESTRICTED = {"sensitive": r"password|passcode|\bssn\b|social security|national id|aadhaar|\bpan\b|passport|bank|card number|iban|routing|sort code", "demographic": r"gender|\brace\b|ethnic|veteran|disab|pronoun|sexual orientation|hispanic|latino", "consent": r"^i (certify|agree|acknowledge|consent|confirm|understand)|terms|privacy policy"}`
    (case-insensitive, applied to the normalized label).
  - `add_answer(path: Path, label: str, answer: str) -> str`: appends an entry with key from
    `normalize(label)` (spaces → `_`, cut to 40, `_2`, `_3`… if taken) and `labels: [label]`. Atomic 0600
    write (tmp + `os.replace`). Returns the key.

### Task 3: Reading a form (`formfill`, part 2)

**Files:**
- Modify: `govaios/formfill.py`
- Test: `tests/test_formfill.py`

**Interfaces:**
- Consumes: `Node` (`govaios/desktop`), and Task 2's `normalize`, `RESTRICTED`, `Bank`.
- Produces:
  - `@dataclass(frozen=True) Field(key: str, label: str, kind: str, options: tuple[str, ...], filled: bool)`.
    `kind` is one of `text`, `textarea`, `combo`, `select`, `radio`, `checkbox`, `multi`, `file`, `other`.
  - `read_form(region: Node) -> list[Field]`, in reading order:
    - `text_field` → `text`; `text_area` → `textarea`; `combo_box` → `combo` (options unknown);
      `popup_button` → `select` (options are the names of its `native:AXMenuItem` children);
      `native:AXSecureTextField` → `other`.
    - Radios that share their nearest ancestor holding ≥2 radios form one `radio` field; options are the radio
      names. 2+ checkboxes in one such container form `multi`; a lone checkbox is `checkbox`.
    - Buttons whose `dom_id` is `resume`, `cover_letter` or `resume-upload-input` → `file`.
    - **Label:** the node's name with trailing `*`/`✱` stripped. If it's empty, the question-text rule
      applies: walk up at most 3 ancestors (for groups, start from the group container). At each one, take its
      nearest previous sibling that contains `text` nodes and no form controls, and join those texts. If no
      text is found, the label is `""`.
    - **Key:** `#<dom_id>` if the field node has one; else `label:<normalize(label)>:<n>`, where `n` counts
      earlier fields with the same normalized label.
    - **`filled`:** text, textarea or combo with a non-empty `value`; radio or checkbox with any `value == "1"`.
  - `restricted(f: Field) -> str | None`: `"secure"` for kind `other`; `"demographic"` for `multi`; else the
    first `RESTRICTED` pattern matching `normalize(f.label)`; else `None`.
  - `answer_for(f: Field, bank: Bank, fields: list[Field]) -> tuple[str, str] | None`: `None` if the label is
    empty, `restricted(f)` is set, `f.filled`, the kind isn't text/textarea/combo/select/radio, another
    field in `fields` has the same normalized label, or the label matches no entry or more than one. For
    `select`/`radio`, the answer must equal exactly one option after `normalize`, and the returned value is
    that option's text. Otherwise returns `(entry.answer, f"bank:{entry.key}")`.
  - `locate(region: Node, f: Field) -> Node | None`: the field's node, found again in a fresh tree by key; for
    `radio`, the group container.

**Interfaces:**
- Consumes: Task 3 (`read_form`, `answer_for`, `restricted`, `locate`); Task 2 (`load_bank`); Task 1 roles and keys.
- Produces:
  - In `govaios/applyfiles.py`:
    - `APPLY_DIR = "apply"`, `BANK = "apply/answers.yaml"`
    - `write_json(home, name, obj)`: 0600, `O_EXCL | O_NOFOLLOW`; removes an older file first.
    - `read_json(home, name) -> dict | None`
    - `remove(home, *names)`
  - `ask.json` = `{"run": <pid>, "fields": [{"key", "label", "kind", "options"}]}`;
    `reply.json` = `{"run": <pid>, "answers": {key: value}}`;
    `result.json` = `{"run": <pid>, "filled": int, "total": int, "yourself": [label, ...], "check": [label, ...]}`.
  - Engine step `{action: fill_form}` uses `self.ctx["page"]` and that page's `form_region` element. Also
    `ASK_TIMEOUT_S = 900` and `FORM_PASSES = 3` in `engine.py`.
  - Each fill: `self.gate("fill_field", "modify", target=label[:80])`, then the fill, then the audit entry
    `action` with `action="fill_field"`, `target=label[:80]`, `source="bank:<key>"|"admin"`,
    `outcome="done"|"mismatch"`. Asking: `self.gate("ask_admin", "read")` once.
  - The admin card's answer for a field is filled the same way, with source `admin`.

**Fill algorithm** (the implementer writes it as stated):
1. `bank = load_bank(home/BANK, user_home())` once; on `BankError`, `Stop("answer bank: <message>")`.
2. Up to `FORM_PASSES` times:
   - take a fresh snapshot and `region = element(f"{page}.form_region", root)`;
   - `fields = read_form(region)`, minus keys already handled;
   - stop if none are left;
   - for each field: if `answer_for` gives a value, fill it; else add it to pending. Already-filled fields go to
     `check`.
3. Fill by kind. Each fill first runs `locate` in a fresh snapshot and skips with "mismatch" if the field is
   gone.
   - `text`/`textarea`: click, `type_text(value)`, re-read, and require `node.value == value`.
   - `combo`: click, `type_text(value)`, press `enter`, re-read, and require the combo's `value == value` or a
     `text` node equal to `value` inside the combo's parent group.
   - `select`: click, `type_text(value)`, press `enter`, re-read, and require `value` or `name == value`.
   - `radio`: click the radio named `value`, re-read, and require its `value == "1"`.
   - On a mismatch for text/textarea/combo: `select_all`, then `delete_back`. Record "mismatch" and move the
     field to `yourself`.
4. Pending fields with a non-empty label, kind in text/textarea/combo/select/radio, and not restricted go to
   `ask.json`; the rest go to `yourself`. Pending restricted fields go to `yourself`; the admin answers those in
   Chrome.
5. If anything was asked: poll `reply.json` every 1 s until `run` matches, `runstate.stopped` →
   `Stop("emergency stop")`, the screen locks → `Stop("screen_locked")`, or `ASK_TIMEOUT_S` passes →
   `Stop("no answer from admin")`. Always remove `ask.json` and `reply.json` in a `finally`. Fill each
   answered field (an empty answer means skip, so it goes to `yourself`).
6. Write `result.json`. Print `apply: filled N of M` (counts only).
