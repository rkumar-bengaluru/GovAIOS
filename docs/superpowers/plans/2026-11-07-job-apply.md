# Job Apply (Greenhouse, Lever) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** From Talk, open one Himalayas job's application form (Greenhouse or Lever), fill it from the admin's
answer bank, ask the admin for the rest, attach the CV, and stop before Submit.

**Architecture:**
- A pure module `govaios/formfill.py` reads a form from the neutral accessibility tree and matches fields to
  the bank by a fixed rule (no model).
- The engine gains `fill_form` and `attach_file` steps. They gate each action, and every keystroke checks
  focus at element level.
- The run (network-less) and the panel exchange 0600 files in the data home, keyed by a run id derived from
  the run ticket.
- The flow `job_apply` and five page schemas wire it together.
- Runs take one input, the job link. It comes from the Talk card, is bound into the ticket, and is passed by
  the launch helper as an env var.

**Tech Stack:** Python 3, PyYAML, pyobjc (macOS AX/CGEvent), pytest. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-07-greenhouse-apply-design.md`

## Global Constraints

- No AI model anywhere in the run-time path. Label-to-answer matching is the fixed rule in Task 2.
- Answer values (bank or admin) never appear in the audit log, stdout/stderr, reports, `result.json` or
  exception messages. Labels (form question text) may.
- **Enter is never pressed in a web page during filling.** Two exceptions: inside a native select menu
  confirmed open (Task 5), and inside the file dialog confirmed focused (Task 5).
- Answers containing control characters (U+0000–U+001F, U+007F) are refused. The one exception is `\n`, and
  only in a `textarea` field.
- The flow has `max_element_risk: modify`. These are rated `submit`, so they can never be clicked:
  - `Submit application` (Greenhouse)
  - `SUBMIT APPLICATION` / `#btn-submit` (Lever)
  - `Autofill my application`
  - `Apply with LinkedIn`
- Flow destinations are exactly `https://www.google.com`, `https://himalayas.app`,
  `https://job-boards.greenhouse.io` and `https://jobs.lever.co`.
- Never auto-filled, always to the admin: secure fields, and labels matching the sensitive, demographic or
  consent patterns (Task 2). Any checkbox group counts as demographic.
- A field that already has a value is never changed.
- Data-home files added (`apply/answers.yaml`, `apply/ask.json`, `apply/reply.json`, `apply/result.json`):
  - mode 0600, opened with `O_NOFOLLOW`, regular files only;
  - `apply/` is 0700 and must not be a symlink (`lstat`).
- `ASK_TIMEOUT_S = 900`; `FORM_PASSES = 3`. The run id is `run_id(ticket) = sha256(ticket.encode()).hexdigest()[:16]`.
- `user_home()` is `govaios.agents.user_home`.
- **No regressions for the working apps:** Gmail brief (`morning_inbox_briefing`), Himalayas → JobLens
  (`himalayas_job_vetting` plus delivery), and governed Claude Code and Codex.
  - Don't edit any existing file under `flows/` or `pages/`. Their bytes make up the approval digest, and a
    change would silently revoke the admin's approvals.
  - Don't change `govaios/hook.py`, `govaios/codex.py` or `govaios/agents.py`.
  - New parameters (`inputs`, `question`) default to today's behaviour.
- Tests: `.venv/bin/python -m pytest -q`; the suite must stay green (722 passed at plan time).
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feat/job-apply`.

## Rulings (where this plan narrows the spec)

- **Picking the job:** `/job-apply` takes a pasted Himalayas job link, not a JobLens list. The panel sandbox
  (`UI_PROFILE`) has no outbound network, so a list is a separate sandbox decision for the admin.
- **The CV is attached as a file only.** Greenhouse's paste mode is deferred.
- **The panel writes "save to my bank" entries when the admin answers;** the run read the bank at its start.
- **No CAPTCHA detection.** The admin submits, and an earlier challenge makes a fill fail read-back.
- **Disabled fields and character limits aren't detected.** A failed read-back sends the field to "fill yourself".
- **A run started from the CLI** (no ticket) never asks; pending fields go to "fill yourself".
- **If Himalayas' Apply opens a new window,** the pinned-window check stops the run. The live test shows which
  happens.
- **Lever:** the Himalayas Apply links seen go straight to `jobs.lever.co/<co>/<id>/apply` (the form), so there
  is no Lever posting page.
- **The app is named "Job Apply"** (`wf.app`), so it doesn't collide with the vetting flow's "JobLens" in Talk.

## Review Focus

1. The page re-renders between reading and filling (React), so node handles go stale. Each fill re-finds its
   field by key in a fresh snapshot. Test in Task 7.
2. A field already has a value (autofill, or the admin typed). It's never touched and is listed under "check".
   Test in Task 7.
3. Two fields share a label with no ids. Both go to the admin. Test in Task 3.
4. The admin never answers, or the run is killed. The timeout stops the run and removes the files; after a kill,
   the panel removes them. Tests in Task 8 and Task 12.
5. The bank is malformed, or edited during a wait. It fails closed with line numbers only, and the run keeps the
   bank as read at its start. Tests in Task 2 and Task 13.

### Task 2: Answer bank and matching rule (`formfill`, part 1)

**Files:** Create `govaios/formfill.py`. Test `tests/test_formfill.py`.

**Interfaces:**
- Produces:
  - `normalize(label: str) -> str`: lower case; drop trailing `*`, `✱` and whitespace; every non-alphanumeric,
    non-space character becomes a space; collapse spaces; strip.
  - `class BankError(ValueError)`: the message holds field names or line numbers only. For YAML errors, build
    it from `e.problem_mark.line + 1`, never `str(e)`.
  - `@dataclass(frozen=True) Entry(key: str, labels: tuple[str, ...], answer: str)`
  - `@dataclass(frozen=True) Bank(entries: tuple[Entry, ...] = (), cv_file: str | None = None)`
  - `load_bank(path: Path, user_home: Path) -> Bank`:
    - a missing file gives `Bank()`;
    - shape `{cv_file?: str, answers: [{key, labels: [str], answer: str}]}`;
    - keys match `[a-z0-9_]{1,40}`, with no duplicates;
    - 1–20 labels per entry, each at most 300 chars;
    - answers of at most 2000 chars, with no control characters except `\n`;
    - at most 300 entries;
    - `apply/` must not be a symlink, and the file is opened `O_NOFOLLOW` and must be regular.
  - `ok_value(value: str, kind: str) -> bool`: the control-character rule from Global Constraints.
  - `cv_path(bank: Bank, user_home: Path) -> Path | None`: `~` means `user_home`. The result must be a regular
    file, not a symlink (`os.lstat`), with its realpath inside `user_home` and suffix `.pdf`, `.doc` or `.docx`.
  - `RESTRICTED`:
    - `"sensitive"`: `r"password|passcode|\bssn\b|social security|national id|aadhaar|\bpan\b|passport|bank|card number|iban|routing|sort code"`
    - `"demographic"`: `r"gender|\brace\b|ethnic|veteran|disab|pronoun|sexual orientation|hispanic|latino"`
    - `"consent"`: `r"^i (certify|agree|acknowledge|consent|confirm|understand)|terms|privacy policy"`

    All three are case-insensitive and applied to `normalize(label)`.
  - `add_answer(path: Path, label: str, answer: str) -> str`:
    - the key is `normalize(label)` with spaces → `_`, cut to 40, and `_2`, `_3`… if taken;
    - the entry gets `labels: [label]`;
    - refuses an answer that fails `ok_value(answer, "textarea")`;
    - writes atomically (0600, tmp + `os.replace`);
    - returns the key.

### Task 3: Reading a form (`formfill`, part 2)

**Files:** Modify `govaios/formfill.py`. Test `tests/test_formfill.py`.

**Interfaces:**
- Consumes: `Node` from `govaios.desktop`, plus Task 2.
- Produces:
  - `FIELD_ROLES = {"text_field", "text_area", "combo_box", "popup_button", "radio", "checkbox"}`
  - `@dataclass(frozen=True) Field(key: str, label: str, kind: str, options: tuple[str, ...], filled: bool)`.
    `kind` is one of `text`, `textarea`, `combo`, `select`, `radio`, `checkbox`, `multi`, `other`.
  - `read_form(region: Node) -> list[Field]`, in reading order:
    - Kinds:
      - `text_field` → `text`; `text_area` → `textarea`; `combo_box` → `combo` (options `()`);
      - `popup_button` → `select`, with options from the names of its `native:AXMenuItem` children;
      - `native:AXSecureTextField` → `other`.
      - Radios under the nearest ancestor holding ≥2 radios form one `radio` field, with the radio names as
        options. 2+ checkboxes in such a container form `multi`; a lone checkbox is `checkbox`.
      - Buttons are not fields.
    - **Label:** the node's name without a trailing `*`/`✱`. If that's empty, use the question-text rule: walk
      up at most 3 ancestors (for groups, start from the group container). At each one, take its nearest
      previous sibling that contains `text` nodes and no `FIELD_ROLES` node, and join its texts, minus a
      trailing `✱`/`*`. If nothing is found, the label is `""`.
    - **Key:** `#<dom_id>` if the node has one; else `label:<normalize(label)>:<n>`, where `n` counts earlier
      fields with the same normalized label. A radio group's key comes from its label.
    - **`filled`:** text, textarea or combo with a non-empty `value`; radio or checkbox with any `value == "1"`.
      For a select, the value must not equal its first option.
  - `restricted(f: Field) -> str | None`: `"secure"` for `other`, `"demographic"` for `multi`, else the first
    matching `RESTRICTED` pattern, else `None`.
  - `answer_for(f: Field, bank: Bank, fields: list[Field]) -> tuple[str, str] | None`: `None` if:
    - the label is empty, the field is restricted, or it's filled;
    - its kind isn't text/textarea/combo/select/radio;
    - another field in `fields` shares its normalized label;
    - the label matches zero entries, or more than one;
    - `not ok_value(answer, kind)`.

    For `select`/`radio`, the answer must equal exactly one option after `normalize`, and the returned value is
    that option's text. Otherwise it returns `(answer, "bank:<key>")`.
  - `locate(region: Node, f: Field) -> Node | None`: the field's node in a fresh tree, by key. For `radio`, the
    group container.

### Task 7: Engine `fill_form`: fills from the bank

**Files:** Modify `govaios/engine.py`. Test `tests/test_engine_apply.py`.

**Interfaces:**
- Consumes: Tasks 2, 3, 5 and 6.
- Produces:
  - Step `{action: fill_form}` on `self.ctx["page"]`, whose schema has a `form_region` element.
  - `self.ctx["apply"] = {"bank": Bank, "filled": int, "total": int, "yourself": [label], "check": [label],
    "pending": [Field]}`.
  - `Runner.write_result()`: writes `result.json` from `ctx["apply"]` when `run_id` is set, and prints
    `apply: filled N of M`.
  - `Runner.fill(f: Field, value: str, source: str) -> bool`.
  - Constants `FORM_PASSES = 3`, `ASK_TIMEOUT_S = 900`.

**`fill(f, value, source)`** (the implementer writes it as stated):
1. Take a fresh snapshot; `identify(self.pages[page], root)` must hold, else `Stop("left the form page")`.
2. `region = element(f"{page}.form_region", root)`; `node = locate(region, f)`. If it's missing, or its role
   isn't in `FIELD_ROLES` (for radio: the option node named `value`), the result is mismatch.
3. `gate("fill_field", "modify", target=f.label[:80], destination=self.d.current_url(self.app))`.
4. By kind:
   - `text`/`textarea`: click node; require `d.focused_is(node)`; `d.type_into(node, value)`.
   - `combo`:
     1. Snapshot the `list` nodes, then click and `type_into`.
     2. Snapshot again. Candidates are nodes whose name or `text()` equals `value`, inside a `list` node that
        wasn't in the earlier snapshot (compare by the path of child indexes from the root).
     3. Exactly one candidate: click it. Otherwise press `escape`, and treat it as a mismatch.
   - `select`: click node; if `d.menu_open()`, `type_text(value)` then press `enter` (in the menu); else
     `escape` and mismatch.
   - `radio`: click the radio node named `value`.
5. Re-read: take a snapshot and `locate`:
   - text/textarea/combo `value == value`;
   - for combo, alternatively a `text` node equal to `value` inside the combo's parent group;
   - select `value` or `name == value`;
   - the clicked radio's `value == "1"`.
6. On a text/textarea/combo mismatch, while `focused_is(node)`, press `select_all` then `delete_back`.
7. Audit `action` with `action="fill_field"`, `target=f.label[:80]`, `source=source`,
   `outcome="done"|"mismatch"`. On a mismatch, add the label to `yourself`.

**`do_fill_form`:**
1. `bank = load_bank(home/BANK, user_home())`; on `BankError`, `Stop(f"answer bank: {e}")`.
2. Up to `FORM_PASSES` passes: read the form, minus keys already handled, and stop when none are left. For each
   field:
   - filled → `check`;
   - `answer_for` gives a value → `fill`;
